4. MAIN/LIVE PIPELINE
----------------------------------------------------------------------
- There is NO separate live/streaming pipeline (no websocket/live entrypoint
  found anywhere in backend/app). The only CV entrypoints are in
  backend/app/api/routes/assessments.py:
    * POST /assessments/{id}/process-video -> calls
      batch_processor.process_video().
    * POST /assessments/{id}/upload-video -> saves upload, calls
      batch_processor.process_video(), then feeds keyframes into
      TrackStateManager + PrimaryWorkerSelector, persists results.
- These use the current pose estimator (PoseEstimator) and call
  assess_posture() indirectly via batch_processor.
- RULA/REBA values do propagate into stored output
  (persist_cv_assessment_results) and into per-track smoothed assessments
  (track_state.py).
- Camera-yaw/side-view validation is present (via batch_processor's gate,
  inherited from estimate_camera_yaw_deg).
- NO remaining references to MediaPipe or an old "4-check" system anywhere
  in backend/app or requirements.txt - the old system appears fully
  removed.
- Caveat: since there's no live/real-time (frame-by-frame streaming)
  entrypoint, "LIVE PIPELINE" really maps to the upload/process-video REST
  flow - there is no continuous live video ingestion path currently
  implemented.
